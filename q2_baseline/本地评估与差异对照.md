## 3. 新代码与我的代码的差异（`q2_baseline/` vs `problem2/`）

### 3.1 数据使用

| 维度 | 新代码 `q2_baseline` | 我的 `problem2` | 影响 |
|---|---|---|---|
| 文本特征 | `text (N,50,768)` float32 **预训练 BERT 时间序列**，每步 768 维直接进网络 | `text_bert (N,3,50)` token id → `nn.Embedding(30523, 96)` 从零学习 | **决定性差异**：训练集只有 3395 条，无法从零学出语义。这是我 test Macro-F1 仅 0.4901 的首要原因 |
| 音频/视觉 | `(50,74)/(50,35)`；掩码优先取显式 `*_mask`，其次非零判据，未对齐时用 `*_lengths` | `(50,74)/(50,35)`；掩码=行 L2 范数 > 1e-8 | 新代码的 `*_lengths` 判据在未对齐数据上更可靠（我此前实测：附件2 的零值主要是长度填充） |
| 标准化 | 每模态按有效位置 mean/std，clip ±10；统计量存入 checkpoint | 仅音频/视觉按有效位置 mean/std；文本是 id 不做标准化 | 思路等价；新代码把统计量写进 checkpoint，便于第三方独立复算 |
| 数据工程 | 直接 `pickle.load` 官方 pkl（948 MB / 2.76 GB） | 自研字节级流式提取（`data_cache.pkl`），为省内存**主动丢弃 `text (N,50,768)`** | 我省了内存，却恰好丢掉了信息量最大的特征 |
| 未对齐分支 | `prepare_unaligned_50.py` 长度感知等时长重采样 + VICReg 自监督 | 无 | 新代码多一条数据版本路线；其 test Macro-F1 0.6178 > 对齐版 0.6041 |

### 3.2 模型结构

| 组件 | 新代码 baseline | 新代码 multiview（residual fusion） | 我的模型 |
|---|---|---|---|
| 单模态编码 | Linear→ReLU→**Conv1d(k=3)**→残差+LayerNorm→掩码均值池化 | Linear→GELU→**GRU(2 层)**→残差+LayerNorm→掩码均值池化 | Linear+LayerNorm+GELU（数值模态）/Embedding（文本）→**BiGRU(1 层)**→掩码均值池化 |
| 融合 | 三路池化直接 `Linear(3H→H)` | 编码表征 **+ 每模态 masked mean/std 的零初始化残差投影** → `Linear(6H→2H)`→…→`Linear(2H→H)` | **动态门控融合**：门控 MLP 输入 `[h_m, 该模态有效率]`→softmax→加权和→融合 MLP |
| 缺失处理 | 掩码乘在池化前；无门控 | 掩码 + 残差旁路 | 掩码在 GRU 前后都乘（防止时间泄漏）；有效率=0 的模态在门控中被 `masked_fill` 屏蔽 |
| 强度回归头 | `Linear(H,1)`，输出无界 | `LayerNorm→Linear(H,1)`，无界 | `Linear(H,1)+tanh`，再 ×3（限幅到 [-3,3]） |
| 规模 | hidden 64，权重 0.45 MB | hidden 128，2 层 GRU | hidden 96，BiGRU，权重 13.4 MB |

## 4. 性能差距归因

1. **文本表示是主因**：新代码直接消费 768 维预训练 BERT 时间表征；我的模型把文本降级为 token id + 从零学习的小 embedding。在 3395 条训练样本上，后者学不到语义，导致我的模型只能靠“类别先验 + 少量词形信号”，这正是它 Macro-F1 停在 0.49、且与纯文本单模态持平的根源。
2. **回归头设计**：我的 `tanh×3` 把强度压到 ±0.3，MAE 0.796；新代码用无界线性头，MAE 0.650–0.674。
3. **融合方式**：我的门控实测退化为“文本恒定占 0.63 权重”，而新代码的**直接拼接**反而更稳；其 residual fusion 变体再补上每模态 masked mean/std 的零初始化旁路，把分类指标进一步提升（reg1 变体 test Macro-F1 0.6106）。
4. **训练/正则策略**：我的 BiGRU + 类别加权 + 连续模态丢弃 + 早停，在 train 上严重过拟合（train acc 0.98 / valid 0.53）；新代码模型小（hidden 64、无递归）、固定 5–6 轮，反而稳定。
5. **数据版本**：新代码额外做了“长度感知重采样”路线，test Macro-F1 0.6178 优于对齐版的 0.6041，且附件3 未对齐版本的预测类别分布与对齐版一致（可作数据版本敏感性证据）。

## 6. 两边可互补的改进建议

1. **新代码侧（优先）**：
   - 把 `--checkpoint` 改为可选，并补一个“仅 baseline”的入口；
   - 用多种子（≥5）重跑最优配置，报告 test 均值±std，避免把 ±0.008 的差异当结论（我可提供现成的运行器）；
   - 把 multiview 的 SSL + 残差融合与 baseline 的简洁训练合并：基于 baseline 结构加 masked mean/std 旁路即可，不必上 2 层 GRU；
   - 可解释性：门控/权重缺失→现有 Q3 已用 backbone 解释，建议在附件2 test 上也报告场景矩阵。
2. **我的 `problem2` 侧（把新代码的优点搬过来）**：
   - **改用 `text (N,50,768)` 稠密文本特征**（最大单项收益）；
   - 回归头去掉 `tanh×3`，或改用 CCC/Huber 组合损失（对应我 P0/P1 建议）；
   - 引入新代码的 `*_lengths`/显式掩码判据与未对齐数据分支；
   - 保留我的评估体系（7 模态组合、覆盖率分层、门控分析、多种子协议）作为新模型的验证工具。
3. **结论**：就第二问而言，**新代码主线（`aligned_baseline.pt` / `unaligned_resampled_baseline.pt` / `residual_fusion_reg1.pt`）全面优于我的旧模型**，建议以新代码为准；我的 `problem2` 代码的价值在于评估体系与鲁棒性协议（多种子、缺失分层、门控诊断），可作为对新代码的验证与补充实验层。
